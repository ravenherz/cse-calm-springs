# Fretboard Lab — Project Rules & Conventions

Static HTML/CSS/JS fretboard app. No build step, no dependencies, no framework. Open `index.html` directly in a browser.

## Files
- `index.html` — markup: controls, `#fretboard` (contains `#string-numbers`, `#string-labels`, `#neck`), `#tip`, `#legend`, `#tipbox`, `#scale-details` (theory panel below the fretboard, shown on BOTH tabs), `#chord-result` (Chord Analyzer panel, chords tab only).
- `js/app.js` — all rendering + interaction. Single IIFE. Uses `window.Music` from music.js.
- `js/music.js` — music theory data/logic (no DOM). Exposes `window.Music`.
- `css/style.css` — all styling. Dark theme, CSS variables at `:root`. (`.bak` files are session backups — ignore them.)

## General conventions
- **No code comments** unless explicitly asked.
- State is a single `state` object (`js/app.js:64`). All controls mutate it, then call `render()`.
- `render()` = `drawBoard()` + `renderLegend()` + `renderTipbox()` + `renderScaleDetails()` + `saveState()`.
- State persists to `localStorage` under key `fretboard-lab-v1`. `loadState()` validates/sanitizes every field; bad values fall back to defaults.
- Environment: Windows PowerShell 5.1, no Node. JS is validated only by brace/paren balance counts, so keep syntax clean.

## String / board orientation
- Strings are stored low→high pitch (`midis[0]` = lowest string, e.g. E for std6). Custom tunings are built by consecutive midi offsets.
- **Rendering flips this**: the lowest string renders at the BOTTOM, the highest at the TOP ("highest string on top").
- `yPx(idx, area)` = `area.topPad + (area.n - idx - 0.5) * area.step`. `idx=0` is the bottom row.
- Left edge column `#string-numbers` shows string numbers top-down: top string = **1**, bottom = **n** (number displayed is `n - i`).
- Next column `#string-labels` shows note names with octave (e.g. `E2`, format = `midiName + floor(midi/12) - 1`, same as the hover tip), clickable → plays the open string.
- **String line thickness grows linearly from top to bottom**: `1.5 + (n-1-i) * 0.55` px — top string is thinnest (high strings), bottom thickest. Line is centered on the row (`top = yPx - h/2`).

## Fretboard geometry (`js/app.js`)
- Linear fret spacing (no log/scale-of-fretboard math). `music.js` `fretFraction` is unused.
- `x(i)`: position % of fret line `i`. `headstock = 10`, `x(i) = 10 + (i / fretCount) * 90`. Fret 0 line sits at 10%.
- `bandCenter(i)`: center of band `i` = `(x(i-1)+x(i))/2`. **Band 0 mirrors fret 1 across the nut**: `x(0) - (bandCenter(1) - x(0))`, so the "0" label and open-note markers sit in the headstock zone left of the nut. `fretFromX(pct)` returns the fret for a click: the fret line `x(i)` is the divider, so `pct ∈ [x(i-1), x(i))` → fret `i`.
- The **nut** is the fret-0 line, 5px wide, metallic gray gradient (base `.fret-line` is 1px). It is centered on `x(0)` via `transform: translateX(-50%)` (important — otherwise its visual center sits ~2.5px right of the true midpoint between the 0 and 1 fret positions). It paints on the lowest layer: `#neck` has `z-index: 0` (stacking context) and `.fret-line.nut` has `z-index: -1`, so strings/lines/inlays/boxes/markers all render above it.
- `leftBound(i)` = `x(i-1) - 0.2*(x(1)-x(0))` (virtual fret line, so open-note rows get the same padding when `i=0`). `rightBound(i)` = `min(100, x(i) + 0.2*(x(1)-x(0)))`. These define CAGED box edges.
- Fret numbers and inlays sit at `bandCenter(i)`. Double inlays (12, 24) are vertical pairs of dots. Fret numbers sit just above the first string: `top: calc(16.5px - 2em)` (the 2em lifts them clear of the top string row).
- Box outline and its top label/play button are shifted up 1em from the natural row geometry: `.caged-box { transform: translateY(-1em) }`, `.box-top { top: 5px }` (the box element itself already carries the offset).
- `#fretboard` min-width 1100px; `#neck` has no left margin (the old 18px margin was removed).

## CAGED system (`state.tab === 'caged'`)
- Tab has **Key**, **Category**, **Scale** and **Mode** controls (category = `.cat-tab` pills, shared `state.scaleCategory`). Scale family/mode are SHARED with the Scales tab (`state.scaleFamily`, `state.modeIndex`). The mode's interval set is built on the CAGED root (`cagedKey`): `scalePcs = ordered intervals + root`; triad = 1·3·5 of that mode (`ordered[0/2/4]`).
- `SHAPE_DEFS` (`js/app.js:10`) — all shapes span EVERY string (`minS=0, maxS=n-1`), no per-shape string range. Each shape is defined by a **`pos2` root string** + its **root-location strings** (documentation). The `pos2` string is the one whose key-root note lands on the **2nd fret of the box** (`lo = rootFretOnPos2 - 1`):
  - `C` color `#ff6b6b` pos2 4 (2nd string), roots on 5th & 2nd strings
  - `A` color `#ffa94d` pos2 1 (5th string), roots on 5th & 3rd strings
  - `G` color `#51cf66` pos2 3 (3rd string), roots on 6th, 3rd & 1st strings
  - `E` color `#4dabf7` pos2 0 (6th string), roots on 6th & 1st strings
  - `D` color `#b197fc` pos2 2 (4th string), roots on 4th & 2nd strings
  - String indices are the standard 6-string core (0=6th/E … 5=1st/e), shifted by `core = max(0, n-6)` for 7+ string instruments. `f` = fret where the `pos2` string plays the root; boxes repeat every octave (`f`, `f+12`, …) and each box is `[f-1, f+3]`.
- **Root on 2nd fret (mandatory)**: every box contains the root note at its 2nd fret (position 2 = fret `lo+1`) by construction, via the shape's `pos2` string.
- **The C-A-G-E-D sequence is built-in**: box starts follow cyclic C → A → G → E → D → C up the neck with +2/+2/+3/+2/+3-fret steps (e.g. C major: C[0,4] → A[2,6] → G[4,8] → E[7,11] → D[9,13]). Each adjacent pair overlaps (connective rule).
- **Box must contain all steps**: `hasAllSteps(lo, hi)` checks every scale pc appears somewhere in the window (all strings). Windows are always 5 frets wide.
- **Incomplete boxes are dropped entirely**: if `lo < 0` or `hi > N`, or the window lacks a step, `addShape` returns without drawing it (no clamping).
- Box rendering: spans `leftBound(visLo)`..`rightBound(visHi)` where `visLo`/`visHi` are the first/last **fret columns that actually contain (pruned, visible) notes** — the outline hugs the notes instead of spanning the full 5-fret window, so empty side columns don't extend it. Vertical padding = half a string row each side (`top = yTop - 15 - step/2`, `height = yBot - yTop + 30 + step`). Label is just `"X shape"` (no chord name). Clicking a box plays its root midi. `fullChart`'s `inBox` check uses `visLo`/`visHi` too.
- **Root connection lines**: each box also draws an SVG polyline (`.shape-lines`, z-index 5, above box outline / below markers) in the shape color connecting the box's **root notes** on its root-location strings (`rootStrings` in `SHAPE_DEFS`: C [1,4], A [1,3], G [0,3,5], E [0,5], D [2,4], shifted by `core`). The root fret per string is the occurrence of the key-root pc inside the window (`while (fr < lo) fr += 12`). Points ordered low→high string; `<2` roots (A shape) → no line. Only rendered for active shapes (boxes exist only for active ones).
- Within a box, only scale notes are shown. Notes are collected via an `overlap` map (note → list of containing shapes), then markers are emitted:
  - `root` → gold (stays gold even when shared).
  - chord tone 3·5 (when `showChordTones` is on) → `chord` class, colored with the shape color.
  - other scale notes → `scale` (blue).
- **Duplicate-pitch rule**: within a box, if the same exact midi pitch appears on 2+ strings, only the occurrence whose string has the smaller **max distance between its notes in the box** (per-string span = hi-fret − lo-fret of that string's notes; ties → lowest string index) is *highlighted*. `pruneDuplicates(notes)` in `computeData` runs per box; each box gets a unique `id` and a `keep` set of `s:fr` (stored in `boxKeep[id]`). The emission loop checks each position against every containing box: if no box keeps it, it still renders with its normal class (`root`/`chord`/`scale`) plus the **`soft`** modifier (`filter: saturate(.5) brightness(.9) opacity(.72)`) — present on the fret and faintly colored like a scale note, never highlighted. `taken` marks it regardless so fullChart never redraws it. Box `notes` (playback) exclude the pruned duplicates (only kept occurrences play). Example: B3 on the 2nd string (span 3) vs 3rd string (span 4) in a C box → the 2nd-string one is highlighted, the 3rd-string one renders softly. Outline `visLo`/`visHi` use the **kept (highlighted)** notes only, so the C box in C Ionian spans 4 columns even though the soft B duplicate sits at fret 4 — it's technically inside the window but has a better location, so it may fall outside the shrunken outline.
- **Overlapping chord tones**: if a chord tone sits inside 2+ boxes, it renders `chord split`: a 3-band gradient — left shape color → chord-tone blue `#7dd3fc` → right shape color (leftmost = smallest `lo`). ~2px smooth transitions between bands (`calc(33.333% ± 1px)`). Shared scale-only notes use the leftmost box's color.
- **"All notes" (fullChart)**: renders every remaining note on the neck. In-box scale notes are skipped (already shown). Notes NOT inside any box get the `soft` class → `filter: saturate(.5) brightness(.9) opacity(.72)` (less color-intense). Notes inside a box that aren't scale notes render as normal `plain`.

## Scales tab (`state.tab === 'scales'`)
- Uses `M.scaleOrdered(family, modeIndex)` (modes rotate the base interval list).
- Root/chord/scale classes: `root` gold, triad tones (1·3·5) `chord` blue, others `scale` blue.
- With `fullChart` off, only scale notes render. With `fullChart` on, all notes render; non-scale notes get `plain` (no `soft` treatment in this tab).
- **`#scale-details` theory panel** (below the fretboard, shown on **both** tabs): `renderScaleDetails()` fills it — header (root + mode/scale name + "mode N of …"), an SVG **interval wheel** (12 chromatic positions; root gold, triad blue, scale tones blue, others dim), the scale **step pattern** (W/H blocks), **degree cells** (Roman numeral + note + interval, color-coded root/triad/scale), an interval **formula** (♭/♯ glyphs via `FORMULA`), and a **character** line (mood words + characteristic interval) from `MODE_INFO`/`SCALE_INFO`. Falls back to a formula-only card when no entry exists. Root = `cagedKey` on the CAGED tab, `scaleKey` on the Scales tab (scale family/mode are shared).

## Scale catalog (`js/music.js`)
- **49 families / 133 playable scales**, organized into **12 categories** via `SCALE_CATS` (`{ id, label, families[] }`), each family listed in exactly one category. Categories: `church` (major), `melodic` (melodicMinor), `harmonic` (harmonicMinor), `harmMajor` (harmonicMajor), `doubleHarm` (doubleHarmonic), `neapolitan` (neapolitanMajor + neapolitanMinor), `symmetric` (wholeTone, augmented, diminished, diminishedHW, chromatic, Messiaen modes 3–7), `penta` (major/minor/suspended/dominant pentatonics + hirajoshi/iwato/insen/pelog/marwa), `hex` (blues, bluesMajor, hexatonicMajor/Minor, prometheus), `bebop` (5 bebop families), `jazz` (dominant, minor/major six-diminished), `world` (persian, enigmatic, spanishPhrygian, todi, purvi, phrygianNatural6, mixolydianAugmented, lydianMinor, hungarianMajor, locrianNatural2).
- Family entries are `{ label, base }` (flat) or `{ label, modes[], base }` (mode family). `modes[0]` is always the family's base scale itself; every `base` starts at 0, is strictly ascending, and fits in [0,11]. `rotateScale` / `scaleOrdered` re-root each mode (validated by a PowerShell data check).
- **Category tabs**: both tab rows have a `<span class="cat-tabs">` (`#scale-cats`, `#caged-cats`) of `.cat-tab` pill buttons (`flex: 1 1 100%` so they sit on their own row). `state.scaleCategory` (default `church`) drives them. Clicking a category sets `state.scaleCategory`; if the current `state.scaleFamily` isn't in it, family resets to the category's first family (mode 0). `familyOptions()` fills `#ctl-scale-family` + `#ctl-caged-family` with only the active category's families (fallback: all families if state is inconsistent). `loadState()` derives the category from the saved family (`catForFamily`). `allScaleKeys()` flattens every category's families — used by `familyOptions` fallback and `chordScales`.
- **Degree Roman numerals** go up to XII (`ROMAN = ['I'..'XII']`) so chromatic (12-note) and Messiaen (9–10 note) scales render steps correctly.

## Chord Analyzer tab (`state.tab === 'chords'`)
- Same fretboard (strings/frets/inlays), but the user **places notes by clicking** the neck and the app **detects the chord** live.
- **Click-to-place**: the `#neck` click handler converts click coords → string via `yArea()`/`yPx` math and fret via `fretFromX(pct)` (see geometry). Clicking empty space appends `{s, f}` to `state.chordNotes`; clicking a placed note removes it. One note per string max. A grid-snapped gold `+` previews placement on hover (`placeGhostPlus`/`gridAt`). `#btn-chord-clear` empties; `#chord-count` shows the tally. `chordNotes` persists to localStorage (sanitized on load).
- **Detection — modular jazz model**: `analyzeChord(midis)` reduces placed midis to a pitch-class set and scores an interpretation for **every candidate root** (`chordScore(c)`: 3rd +4, 7th +4, 6th +2, perfect 5th +3, altered 5th +1, sus +3, dim7 +5, dim +2, extensions +1 each). The primary is chosen by **slash-chord rule**: if the lowest (bass) note has a valid reading and it's not "exotic" (altered/dim/aug) it anchors the chord (`C` major stays `C`, `Am` stays `Am`); only when the bass-rooted reading is exotic or missing is the strongest other-root reading promoted and shown as a **slash chord** (`RootSuffix/Bass`) — e.g. E–G–C → `C/E`, A–C#–E → `A/C#`, Bb–D–F#–A → `Bbmaj7#5/F#`. Ties break toward the bass note. `interpretChord(I)` builds a descriptor `c` from the interval set: third (3/♭3), seventh (♭7/7), fifth (5/♭5/♯5/none), shell (6th / dim7 / dim / aug), sus (2/4), and extension flags (♭9 / 9 / ♯9 / 11 / ♯11 / ♭13 / 13) with cross-condition guards (#11 only over a perfect 5th, 13 only when the 5th isn't altered, 9 hidden in sus2). `describeChord(c)` renders the symbol compositionally in stack order — third → seventh/shell → extensions → altered 5th → `(no5)`/`(no3)` annotations — e.g. `m9(no5)`, `13#11`, `maj7#11`, `7b5b9`, `m6/9`, `madd4`, `dim7`, `7sus4`, `5`. There is **no finite `CHORD_TYPES` table**; any pc set is interpreted.
- **Alternatives**: the same `readings` list (excluding the primary) provides up to 2 "Also heard as" entries, ranked by `chordScore`.
- **Rendering**: `renderChordNotes(midis, area)` (from `drawBoard`) emits markers for all placed notes — the root note gold (`.marker.root`), every other note vibrant blue (`.marker.scale`), same look as scale notes on the Scales tab. Role labels come from `roleLabel(iv, c)` and are extension-aware: a 9th in a `13` chip reads "13", a ♯9 reads "#9", a plain 4 stays "4". `renderChordResult()` fills `#chord-result`: big root+suffix symbol (with `/Bass` appended for slash chords), quality sub-line (slash chords say "slash chord — X in the bass"), note chips (root gold / in-chord blue / outside muted), alternatives, and a **scale proposal** block. `labelFor` maps pc → role label for both chips and markers. `#btn-chord-play` plays the placed notes as an arpeggio through the shared `playSequence`/groove engine (rooted at the detected chord root), with `data-sf` marker highlighting — the `#ctl-playback` panel (BPM + groove) is shown on the chords tab too.
- **Scale proposals** (`chordScales(rootPc, intervals)`, shown for matched chords only): every library scale/mode rooted on the chord root (rooted on the primary chord root, not the slash bass) is checked against the chord's intervals. Scales containing **every** chord note are listed as full matches; scales containing the chord **skeleton** (`essentialIntervals(c)`: root + 3rd/♭3rd + 5th + 7th/6th, or sus/dim/aug shell) but clashing only on extensions are listed dimmed with `— missing b9`-style annotations. Iterates **all 49 families / 133 scales** via `allScaleKeys()` (previously a hardcoded 9-key list); duplicate pc-sets are deduped (e.g. the `dominant` Mixolydian family collapses into the major mode, Neapolitan Minor's Mixolydian/Lydian Dominant/Locrian #2 into the existing families). Lists are capped (8 full + 6 partial, with a `+N more` dashed chip) so plain triads/power chords don't overflow the panel. E.g. `Cmaj7` → C Ionian, C Lydian; `Dm7` → D Dorian, D Aeolian, D Phrygian + minor pentatonic/blues; `C7` → C Mixolydian, C Lydian Dominant, C Mixolydian ♭6; `Bbmaj7#5` → Bb Lydian Augmented, Bb Ionian ♯5.
- **Scale ghost preview** (single-select toggle): each proposed scale renders as a `<button class="cr-scale-chip">` (full → solid, partial → dimmed, `+N more` → non-interactive dashed span). Clicking toggles the module-level `scaleSel = {rootPc, name, ivs}` (ivs = the scale's ordered relative intervals from `data-pcs`, degree order preserved since all `scaleOrdered` outputs are ascending); clicking a different chip replaces it, clicking the active one clears it — only one scale at a time. The active chip gets `.cr-scale-chip.active` (chord-blue fill) and a `ghost notes: …` hint appears in the block title. `renderScaleGhost(midis, area)` renders the scale's notes across all strings/frets as **full `.marker.plain.soft` markers** — the same greyish out-of-scale-note styling as the CAGED tab's "All notes" — showing note name (`names()[pc]`), interval (`M.INTERVALS[rel]` vs the chord root), and Roman step (`ROMAN[ivs.indexOf(rel)]`), each gated by the shared `state.showNames` / `showIntervals` / `showSteps` toggles. Ghost markers are `pointer-events: none`, `z-index: 3` (below the vibrant placed-note markers at 10, above strings), and carry **no** `data-sf` so arpeggio playback only highlights real notes. `renderChordNotes` re-validates `scaleSel` every render (scale must still be a proposal for the current chord root) and clears it otherwise, so the ghost never goes stale; `renderChordNotes` runs before `renderScaleGhost` in `drawBoard`.
- `computeData()` returns empty markers for the chords tab; `#scale-details` is hidden here (`applyTabUI`); the playback panel stays caged-only. Legend shows a placement hint.

## Markers (`makeMarker`, `js/app.js:307`)
- 30px circle, `translate(-50%,-50%)`, centered on `bandCenter(fret)`, vertically on the string row.
- Markup: `.mtop` (note name `.mn` + Roman step `.ms`), then a 1px divider `.ml` (only when an interval is shown), then interval `.mi`.
- **Steps are Roman numerals** (`ROMAN = ['I'..'XII']`, `js/app.js:19`), 1-indexed by degree (covers scales up to 12 notes).
- Interval names come from `M.INTERVALS` (e.g. `R`, `b2`, `2` ...).
- CSS vars: `--mc` (shape/chord color), `--mcL` (split left), `--mcR` (split right). `makeMarker(pc, fret, stringIdx, midis, label, cls, color, colorR)`.
- Classes: `marker root|chord|scale|plain|chord split`, plus `soft`. `.marker.root` = gold w/ glow; `.marker.chord` = `var(--mc)` w/ colored shadow; `.marker.scale` = `--blue`; `.marker.plain` = `rgba(255,255,255,.07)`, text `--muted`.

## Controls / state fields (`js/app.js:64`)

## Tunings (`js/music.js`)
`TUNINGS` entries: `{ id, label, strings, midi[] }` ordered low→high pitch. Custom tuning UI edits `customPcs` (pitch classes), which `customMidi()` expands to consecutive midis.

## Misc
- Sound: WebAudio triangle osc + lowpass, gain envelope, ~1.2s.
- **Arpeggio player**: `playSequence(notes, rootOverride)` schedules notes at `gap = 60000/bpm` ms; `orderNotes(notes, rootOverride)` applies the groove (`upsideDown`, `bothFromDown`, `bothFromUp`, `lowestRoot`, `upperRoot`, default `downsideUp` = ascending) and marks `.marker.playing` for ~`min(380, gap*0.75)` ms. Used by CAGED boxes (root = `rootPc()`) and by the chords tab's `#btn-chord-play` (root = detected chord root). `#ctl-bpm` (40–300) + `#ctl-groove` selects live in the playback panel.
- `#tip` tooltip follows mouse over the board; `#tip` content built in `makeMarker` hover. Positioned **right/below the cursor**: `left = clientX - rect.left + 14`, `top = clientY - rect.top + 20`, clamped to `rect.width - 160`.
- "All notes" checkbox id `#ctl-full`; chord-tone emphasis checkbox `#ctl-chordtones`; root-lines checkbox `#ctl-rootlines`. Playback panel `#ctl-playback` is shown on the CAGED and chords tabs, hidden on the Scales tab.
- Legend: CAGED tab has no `plain` swatch entry; scales tab adds one only when `fullChart` is on.
