# Fretboard Lab — Project Rules & Conventions

Static HTML/CSS/JS fretboard app. No build step, no dependencies, no framework. Open `index.html` directly in a browser.

## Files
- `index.html` — markup: `#ctl-main-controls` (shared + tab strips), `#ctl-playback` (tab extras + BPM/groove), `#fretboard` (`#string-numbers`, `#string-labels`, `#neck`), `#tip`, `#ctx-menu`, `#legend`, `#tipbox`, `#chord-result` (chords only), `#scale-details` (CAGED + Scales; Chord Analyzer when a proposal is selected or ✦-wired), `#profiles-panel` + shared `.modal-overlay`/`.modal`. Static chrome uses `data-i18n` / `data-i18n-attr`.
- `i18n/en.json`, `i18n/ru.json` — editable UI vocabulary sources. Served as `i18n/en.js` / `i18n/ru.js` (script tags). See **i18n** below.
- `css/style.css` — layout/structure. Color tokens are `var(--*)` only (fonts: **Outfit** `--font-ui`, **IBM Plex Mono** `--font-mono` from Google Fonts in `index.html`). (`.bak` files are session backups — ignore them.)
- `css/dark.css`, `css/light.css` — `:root` color palettes (`color-scheme` + all color vars). Dark is the default and matches the previous look. Loaded via `#theme-css`; header `#ctl-theme` switches and persists `localStorage.fretboard-lab-theme` (`dark`|`light`). Early inline script in `index.html` applies the stored theme before paint.

### i18n
**Required for every new user-facing string.** Do not ship hardcoded UI copy in JS/HTML. English in `i18n/en.json` is mandatory; Russian in `i18n/ru.json` is the override. Runtime always falls back to English (`FretI18n` merge + `resolve`).

#### Checklist when adding UI
1. Add keys + English values to `i18n/en.json` first (complete — UI must never show raw key paths).
2. Add matching keys to `i18n/ru.json` (may omit temporarily; missing keys show English).
3. Regenerate `i18n/en.js` / `i18n/ru.js` from the JSON sources.
4. Wire static chrome with `data-i18n` / `data-i18n-attr`; dynamic UI with `t()` or existing display helpers.
5. Keep theory **identity** in English in code (family ids, English mode names for `modeInfo` keys, CAGED letters). Put **display** names in vocab JSON.

#### Mechanics
- Edit `i18n/{lang}.json`, then regenerate matching `i18n/{lang}.js` (same object passed to `FretI18n.register`). Scripts load with the other modules — no `fetch`, works on `file://` and any static/Spring path that already serves `.js`.
- Languages: **en** (default / fallback) and **ru**. Boot applies the stored language synchronously from registered vocabs. Header `#ctl-lang` switches via `applyLang`; persists `localStorage.fretboard-lab-lang`. Theme labels use `theme.*` keys; picker is `#ctl-theme` (separate from language).
- `FretI18n.t('dot.path', { count, … })` — `{placeholders}`; plural keys `path_one` / `path_other` when `vars.count` is set. `raw(path)` for non-string values (arrays/objects).
- Static markup: `data-i18n="key"` (text) or + `data-i18n-attr="title"`; applied via `FretI18n.applyDom` before `init()` and again on language change.
- Dynamic UI (legend, tipbox, chord result, ctx menu, profiles modals) calls `t()` at render time.
- `scaleCats.{id}.label` / `.short` — Explore `#explore-cats` pills and Chord Analyzer scale-group headers. `Music.SCALE_CATS` keeps only `{ id, families[] }`.
- `scales.{familyKey}.label` / `.short` / `.modes[]` — family/mode display names. English strings in `Music.SCALES` remain theory identity; UI uses `scaleDisplayName` / `scaleFamilyLabel` / `scaleModeLabel`.
- `modeInfo.{EnglishModeName}` / `scaleInfo.{familyKey}` — scale-details flavor (`mood[]`, `char`, `desc`) via `theoryInfo()`.
- `noteNames.sharp` / `noteNames.flat` — pitch-class labels (EN letters; RU solfège). `names()` / `midiLabel()`; `Music.SHARP` / `FLAT` are English fallbacks.
- Allowed non-i18n: lead-sheet quality marks (`m`, `maj7`…), numeric/interval formulas, native language-picker option labels (`English` / `Русский`).

Keep theory/UI split: new chord/scale math goes in `music.js` / `chords.js`; board math in `geometry.js` / `caged.js`; guitar CRUD in `profiles.js`; DOM orchestration stays in `app.js`.

### Chord symbol parts (internal naming)
Follows **lead-sheet chord symbols** (jazz/pop chord-symbol shorthand) — not figured bass, Roman numerals, or Nashville numbers. Same stack as Open Music Theory / common lead-sheet grammar: root → quality → extensions/alterations → optional slash bass. Major triad quality is implied when unmarked; only minor writes `m`. Refs: [Open Music Theory — Chord Symbols](https://viva.pressbooks.pub/openmusictheory/chapter/chord-symbols/), [Wikipedia — Chord names and symbols (jazz and pop music)](https://en.wikipedia.org/wiki/Chord_names_and_symbols_(jazz_and_pop_music)), [Tagg — Lead sheet chords](https://tagg.org/articles/epmow/leadsheetchords.html).

Example: `Bbmaj7#5/F#` → **Bb** + **maj7** + **#5** + **/F#** (no minor quality).

| Part | Field / class | Meaning | Display |
|------|----------------|---------|---------|
| **root** | `rootName` / `.cr-root` | Chord root pitch-class name | Baseline, large |
| **quality** | `quality` / `.cr-quality` | Triad quality mark — only `m` when minor; **absent** for major (implied major; tip spells it `major`) | Baseline, large (with root) |
| **extension** | `extension` / `.cr-extension` | 6 / 7 / maj7 / 9 / 11 / 13 / add* / dim / aug / sus* / 5 / Maj7 (after `m`) | Raised, smaller |
| **alteration** | `alterations[]` + `parens[]` / `.cr-alteration` | Tone alters (`#5`, `b5`, `b9`…) and omissions (`no5`, `no3`); parens merge as `(b9,no5)` | Raised, smaller |
| **bass** | `bassName` when `slash` / `.cr-bass` | Slash-chord bass note | Baseline, large |

`suffix` remains the flat concatenation `quality + extension + alterations + (parens)` for tests, alternatives, and scale titles. Prefer the structured fields in new UI/code.

### Theory tests (`test.html`)
- Open [`test.html`](test.html) in a browser (same folder; file:// or any static server). Not linked from the main app.
- Scripts: `music.js` → `chords.js` → `js/tests/runner.js` → `js/tests/fixtures.js`.
- **`lock`** cases = correct behavior that must stay green when heuristics change (scales + chord symbols).
- **`known`** cases = desired fixes that currently fail (amber “KNOWN”); promote to `lock` when fixed.
- Strict pass = all `lock` green. Prefer adding a `lock` fixture for any theory bug you fix; add `known` first when documenting debt before a fix.
- When changing `music.js` / `chords.js`, re-open `test.html` and confirm lock stays green.

## Controls layout (HTML)
Two stacked cards above the board. **Top section is always shared**; **second strip / playback groups are tab-only**.

### `#ctl-main-controls` (`.card.controls`)
1. **`#ctl-shared`** — unified for every board tab (hidden only on Profiles), grouped for scanability:
   - `#ctl-guitar` chip
   - **Display** cluster (`#ctl-display`) — Names · Degrees · Intervals · Notes (sharps/flats)
   - **Sound** cluster (`#ctl-sound-cluster`) — On (`#ctl-sound`)
   - **More** (`#ctl-more` `<details>`) — All notes (`#ctl-full`)
2. **Tab strip** (one visible via `applyTabUI`, dashed top via `.tab-controls`):
   - `#ctl-explore` — Explore · `#explore-cats` · Root / Scale / Mode · **Layers** (`#ctl-caged-layer` CAGED shapes)
   - `#ctl-chords` — Chord Analyzer · `#chord-count` · Play / Clear

### `#ctl-playback` (`.card.playback`)
Hidden on Profiles. Groups stack with dashed dividers:
1. **`#ctl-chord-opts`** (chords only) — Simple vs Compound intervals
2. **`#ctl-caged-shapes`** (Explore) — shape buttons + Root lines when `showCagedShapes`; Chord tones always
3. **`#ctl-playback-controls`** (when Sound on) — BPM · Groove

Tabs are **Explore · Chord Analyzer · Profiles**. Legacy `caged` / `scales` tabs migrate to `explore` (`showCagedShapes` true / false).

## General conventions
- **No code comments** unless explicitly asked.
- State is a single `state` object (`js/app.js`). All controls mutate it, then call `render()`.
- `render()` = `syncBoardSource()` + `renderGuitarChip()` + `drawBoard()` + `renderLegend()` + `renderTipbox()` + `renderScaleDetails()` + `saveState()` (profiles tab early-returns after `profiles.renderProfiles()`).
- State persists to `localStorage` under key `fretboard-lab-v1`. `loadState()` / `sanitizeState` validate every field; bad values fall back to defaults.
- Environment: Windows PowerShell 5.1, no Node. JS is validated only by brace/paren balance counts, so keep syntax clean.

## String / board orientation
- Strings are stored low→high pitch (`midis[0]` = lowest string, e.g. E for std6). The midi array comes from the active guitar profile (see Board source) or the built-in std6 default.
- **Rendering flips this**: the lowest string renders at the BOTTOM, the highest at the TOP ("highest string on top").
- `FretGeom.yPx(idx, area)` = `area.topPad + (area.n - idx - 0.5) * area.step`. `idx=0` is the bottom row. `app.js` wraps as `yPx` / `yArea()` → `FretGeom.yArea(state.stringCount)`.
- Left edge column `#string-numbers` shows string numbers top-down: top string = **1**, bottom = **n** (number displayed is `n - i`).
- Next column `#string-labels` shows note names with octave (e.g. `E2`, format = `midiName + floor(midi/12) - 1`, same as the hover tip), clickable → plays the open string.
- **String line thickness grows linearly from top to bottom**: `1.5 + (n-1-i) * 0.55` px — top string is thinnest (high strings), bottom thickest. Line is centered on the row (`top = yPx - h/2`).

## Fretboard geometry (`js/geometry.js` → `window.FretGeom`)
- Linear fret spacing (no log/scale-of-fretboard math). `music.js` `fretFraction` is unused.
- `x(i, fretCount)`: position % of fret line `i`. `headstock = 10`, `x = 10 + (i / fretCount) * 90`. Fret 0 line sits at 10%. `app.js` wraps `const x = (i) => G.x(i, state.fretCount)` (same for `bandCenter` / `leftBound` / `rightBound` / `fretFromX`).
- `bandCenter(i, fretCount)`: center of band `i` = `(x(i-1)+x(i))/2`. **Band 0 mirrors fret 1 across the nut**: `x(0) - (bandCenter(1) - x(0))`, so the "0" label and open-note markers sit in the headstock zone left of the nut. `fretFromX(pct, fretCount)` returns the fret for a click: the fret line `x(i)` is the divider, so `pct ∈ [x(i-1), x(i))` → fret `i`.
- The **nut** is the fret-0 line, 5px wide, metallic gray gradient (base `.fret-line` is 1px). It is centered on `x(0)` via `transform: translateX(-50%)` (important — otherwise its visual center sits ~2.5px right of the true midpoint between the 0 and 1 fret positions). It paints on the lowest layer: `#neck` has `z-index: 0` (stacking context) and `.fret-line.nut` has `z-index: -1`, so strings/lines/inlays/boxes/markers all render above it.
- `leftBound(i)` = `x(i-1) - 0.2*(x(1)-x(0))` (virtual fret line, so open-note rows get the same padding when `i=0`). `rightBound(i)` = `min(100, x(i) + 0.2*(x(1)-x(0)))`. These define CAGED box edges.
- Fret numbers and inlays sit at `bandCenter(i)`. Double inlays (12, 24) are vertical pairs of dots. Fret numbers sit just above the first string: `top: calc(16.5px - 2em)` (the 2em lifts them clear of the top string row).
- Box outline and its top label/play button are shifted up 1em from the natural row geometry: `.caged-box { transform: translateY(-1em) }`, `.box-top { top: 5px }` (the box element itself already carries the offset).
- `#fretboard` min-width 1100px; `#neck` has no left margin (the old 18px margin was removed).

## Explore tab (`state.tab === 'explore'`)
- Single theory workspace replacing the old CAGED + Scales tabs. Controls: category pills (`#explore-cats`), Root / Scale / Mode (`#ctl-explore-*`), and **Layers → CAGED shapes** (`state.showCagedShapes`, default on).
- Root is `state.scaleKey` (`cagedKey` kept in sync for persistence compat). Family/mode: `state.scaleFamily` / `state.modeIndex` / `state.scaleCategory`.
- **`showCagedShapes` on**: `FretCaged.computeData({ showCagedShapes: true, … })` draws CAGED boxes (same rules as before). Shape buttons + root lines show in playback.
- **`showCagedShapes` off**: full-neck scale view (former Scales tab). Chord tones still apply; root-line / shape UI hides.
- Board data: `FretCaged.computeData(opts)`. `SHAPE_DEFS` in `js/caged.js` — all shapes span EVERY string (`minS=0, maxS=n-1`). Each shape is a **`pos2` root string** + **root-location strings**:
  - `C` color `#ff6b6b` pos2 4 (2nd string), roots on 5th & 2nd strings
  - `A` color `#ffa94d` pos2 1 (5th string), roots on 5th & 3rd strings
  - `G` color `#51cf66` pos2 3 (3rd string), roots on 6th, 3rd & 1st strings
  - `E` color `#4dabf7` pos2 0 (6th string), roots on 6th & 1st strings
  - `D` color `#b197fc` pos2 2 (4th string), roots on 4th & 2nd strings
  - String indices are the standard 6-string core (0=6th/E … 5=1st/e), shifted by `core = max(0, n-6)` for 7+ string instruments. `f` = fret where the `pos2` string plays the root; boxes repeat every octave (`f`, `f+12`, …) and each box is `[f-1, f+3]`.
- **Root on 2nd fret (mandatory)**: every box contains the root note at its 2nd fret (position 2 = fret `lo+1`) by construction, via the shape's `pos2` string.
- **The C-A-G-E-D sequence is built-in**: box starts follow cyclic C → A → G → E → D → C up the neck with +2/+2/+3/+2/+3-fret steps (e.g. C major: C[0,4] → A[2,6] → G[4,8] → E[7,11] → D[9,13]). Each adjacent pair overlaps (connective rule).
- **Box must contain all steps**: `hasAllSteps(lo, hi)` checks every scale pc appears somewhere in the window (all strings). Windows are always 5 frets wide.
- **Incomplete boxes are dropped entirely**: if `lo < 0` or `hi > N`, or the window lacks a step, `addShape` returns without drawing it (no clamping).
- Box rendering: spans `leftBound(visLo)`..`rightBound(visHi)` where `visLo`/`visHi` are the first/last **fret columns that actually contain (pruned, visible) notes** — the outline hugs the notes instead of spanning the full 5-fret window, so empty side columns don't extend it. Vertical padding = half a string row each side (`top = yTop - 15 - step/2`, `height = yBot - yTop + 30 + step`). Label is just `"X shape"` (no chord name). Clicking a box plays its root midi. `fullChart`'s `inBox` check uses `visLo`/`visHi` too.
- **Root connection lines**: each box also draws an SVG polyline (`.shape-lines`, z-index 5, above box outline / below markers) in the shape color connecting the box's **root notes** on its root-location strings (`rootStrings` in `SHAPE_DEFS`: C [1,4], A [1,3], G [0,3,5], E [0,2,5], D [2,4], shifted by `core`). The root fret per string is the occurrence of the key-root pc inside the window (`while (fr < lo) fr += 12`). Points ordered low→high string; `<2` roots (A shape) → no line. Only rendered for active shapes (boxes exist only for active ones).
- Within a box, only scale notes are shown. Notes are collected via an `overlap` map (note → list of containing shapes), then markers are emitted:
  - `root` → gold (stays gold even when shared).
  - chord tone 3·5 (when `showChordTones` is on) → `chord` class; other scale notes → `scale`. **Both** use the owning shape’s color (`.shaped` + `--mc`); root stays gold.
  - other scale notes → `scale` (blue).
- **Duplicate-pitch rule**: within a box, if the same exact midi pitch appears on 2+ strings, only the occurrence whose string has the smaller **max distance between its notes in the box** (per-string span = hi-fret − lo-fret of that string's notes; ties → lowest string index) is *highlighted*. `pruneDuplicates(notes)` in `FretCaged.computeData` runs per box; each box gets a unique `id` and a `keep` set of `s:fr` (stored in `boxKeep[id]`). The emission loop checks each position against every containing box: if no box keeps it, it still renders with its normal class (`root`/`chord`/`scale`) plus the **`soft`** modifier (`filter: saturate(.5) brightness(.9) opacity(.72)`) — present on the fret and faintly colored like a scale note, never highlighted. `taken` marks it regardless so fullChart never redraws it. Box `notes` (playback) exclude the pruned duplicates (only kept occurrences play). Example: B3 on the 2nd string (span 3) vs 3rd string (span 4) in a C box → the 2nd-string one is highlighted, the 3rd-string one renders softly. Outline `visLo`/`visHi` use the **kept (highlighted)** notes only, so the C box in C Ionian spans 4 columns even though the soft B duplicate sits at fret 4 — it's technically inside the window but has a better location, so it may fall outside the shrunken outline.
- **Overlapping shapes**: any non-root note inside 2+ boxes renders `.shaped.split` — a **vertical half-and-half** gradient (`--mcL` | `--mcR`). Left = shape with smaller window `lo` (further left on the neck); right = largest `lo`. Roots stay solid gold (no split).
- **"All notes" (fullChart)**: renders every remaining note on the neck. In-box scale notes are skipped (already shown). Notes NOT inside any box get the `soft` class → `filter: saturate(.5) brightness(.9) opacity(.72)` (less color-intense). Notes inside a box that aren't scale notes render as normal `plain`.

- Full-scale path (layer off): `M.scaleOrdered`; root gold, triad `chord`, others `scale`; `fullChart` adds `plain` non-scale notes.
- **`#scale-details`**: Explore uses `scaleKey` + family/mode; Chord Analyzer uses selected/wired proposal; hidden otherwise.

## Scale catalog (`js/music.js`)
- **49 families / 133 playable scales**, organized into **12 categories** via `SCALE_CATS` (`{ id, families[] }`; display names in `i18n` `scaleCats`), each family listed in exactly one category. Categories: `church` (major), `melodic` (melodicMinor), `harmonic` (harmonicMinor), `harmMajor` (harmonicMajor), `doubleHarm` (doubleHarmonic), `neapolitan` (neapolitanMajor + neapolitanMinor), `symmetric` (wholeTone, augmented, diminished, diminishedHW, chromatic, Messiaen modes 3–7), `penta` (major/minor/suspended/dominant pentatonics + hirajoshi/iwato/insen/pelog/marwa), `hex` (blues, bluesMajor, hexatonicMajor/Minor, prometheus), `bebop` (5 bebop families), `jazz` (dominant, minor/major six-diminished), `world` (persian, enigmatic, spanishPhrygian, todi, purvi, phrygianNatural6, mixolydianAugmented, lydianMinor, hungarianMajor, locrianNatural2).
- Family entries are `{ label, base }` (flat) or `{ label, modes[], base }` (mode family). `modes[0]` is always the family's base scale itself; every `base` starts at 0, is strictly ascending, and fits in [0,11]. `rotateScale` / `scaleOrdered` re-root each mode (validated by a PowerShell data check).
- **Category tabs**: `#explore-cats` `.cat-tab` pills (`flex: 1 1 100%`). `state.scaleCategory` (default `church`). Clicking sets category; if current family isn't in it, family resets to the category's first (mode 0). `familyOptions()` fills `#ctl-explore-family`. `allScaleKeys()` flattens every category for fallbacks / `chordScales`.
- **Degree Roman numerals** are always chromatic (`CHROMATIC_ROMAN`: `I`, `bII`, `II`…`VII`) relative to the root — never scale-order I–VII.

## Chord Analyzer tab (`state.tab === 'chords'`)
- Same fretboard (strings/frets/inlays), but the user **places notes by clicking** the neck and the app **detects the chord** live.
- **Click-to-place**: the `#neck` click handler converts click coords → string via `yArea()`/`yPx` math and fret via `fretFromX(pct)` (see geometry). Clicking empty space appends `{s, f}` to `state.chordNotes`; clicking a placed note removes it. One note per string max. A grid-snapped placement ghost previews on hover (`placeGhostPlus`/`gridAt`): transparent fill, gold outline + glow ring only, and a corner `+` (`.place-plus`) matching the pinned-root `*` (`.pin-star`) style. `#btn-chord-clear` empties; `#chord-count` shows the tally. `chordNotes` persists to localStorage (sanitized on load).
- **Detection — modular jazz model** (`js/chords.js` on `Music`): `M.analyzeChord(midis, forcedRoot, { names, compoundIntervals })` reduces placed midis to a pitch-class set and scores an interpretation for **every candidate root** (`chordScore(c)`: 3rd +4, 7th +4, 6th +2, perfect 5th +3, altered 5th +1, sus +3, dim7 +5, dim +2, extensions +1 each). The primary is chosen by **slash-chord rule**: if the lowest (bass) note has a valid reading and it's not "exotic" (altered/dim/aug) it anchors the chord (`C` major stays `C`, `Am` stays `Am`); only when the bass-rooted reading is exotic or missing is the strongest other-root reading promoted and shown as a **slash chord** (`RootSuffix/Bass`) — e.g. E–G–C → `C/E`, A–C#–E → `A/C#`, Bb–D–F#–A → `Bbmaj7#5/F#`. Ties break toward the bass note. `interpretChord(I)` builds a descriptor `c` from the interval set: third (3/♭3), seventh (♭7/7), fifth (5/♭5/♯5/none), shell (6th / dim7 / dim / aug), sus (2/4), and extension flags (♭9 / 9 / ♯9 / 11 / ♯11 / ♭13 / 13) with cross-condition guards (#11 only over a perfect 5th, 13 only when the 5th isn't altered, 9 hidden in sus2). `describeChord(c)` renders the symbol compositionally in stack order — third → seventh/shell → extensions → altered 5th → `(no5)`/`(no3)` annotations — e.g. `m9(no5)`, `13#11`, `maj7#11`, `7b5b9`, `m6/9`, `madd4`, `dim7`, `7sus4`, `5`. There is **no finite `CHORD_TYPES` table**; any pc set is interpreted.
- **Alternatives**: the same `readings` list (excluding the primary) provides up to 2 "Also heard as" entries, ranked by `chordScore`.
- **Rendering**: `renderChordNotes(midis, area)` (from `drawBoard`) emits markers for all placed notes — the root note gold (`.marker.root`), every other note vibrant blue (`.marker.scale`), same look as scale notes on the Scales tab. Role labels come from `M.roleLabel(iv, c, state.compoundIntervals)` gated by **`state.compoundIntervals`** (`#ctl-compound` in `#ctl-chord-opts`, above the Playback divider): **Compound** (default) is extension-aware — a 9th in a `13` chord reads `9`, ♯9 → `#9`, plain 4 stays `4`; **Simple** always uses within-octave labels (`2`, `4`, `6`, `b2`…). `M.chordIntervalText` / `M.chordIntervalFull` (same compound flag) mirror that for the Intervals toggle and tip (`M9`/`P11`/`M13`… vs `M2`/`P4`/`M6`). `renderChordResult()` fills `#chord-result` as a vertical stack (`.cr-stack`): **symbol** → **Notes** chips → **Scales that fit** (full then partial). Scale chips are clustered by `SCALE_CATS` family (`.cr-scale-group` + sticky `.cr-scale-group-label`). Hovering `.cr-name` shows the shared `#tip` table for chord-symbol parts. When `#scale-details` is open, the two cards join visually (shared edge, no double radius). `analyzeChord` stores `c` + `labelFor` on the result. `#btn-chord-play` arpeggiates via `playSequence` (root = detected chord root); `#ctl-playback` shows chord-opts + (when Sound on) BPM/groove.
- **Scale proposals** (`M.chordScales(rootPc, intervals, { names, compoundIntervals, scaleRoot })`, shown for matched chords only): chord tones are checked against every library scale/mode. Default **`scaleRoot` = chord root** (chord-scale view: `Dm7` → D Dorian…). Optional UI **Key** override (`.cr-scale-key`) sets `scaleRoot` to another pitch class so matching is tonal-center style (`Dm7` + Key F → F Ionian…): intervals are remapped `(chordRoot + iv − scaleRoot) mod 12` before containment tests; missing-tone labels stay in chord-role language. Key **follows** the chord root until the user changes it; **↺** restores follow. Pin / ghost / chip labels use the proposal Key, not the slash bass. Each entry includes `family` + `modeIndex` (first pc-set wins on dedupe). Full = every chord tone in the scale; partial = skeleton (`essentialIntervals(c)`) in the scale with `— missing …` for clashing extensions. Iterates **all 49 families / 133 scales** via `allScaleKeys()`; duplicate pc-sets are deduped. All full and partial matches are listed (no cap), grouped under category headers from `SCALE_CATS` (Church, Melodic Minor, …). E.g. `Cmaj7` → C Ionian, C Lydian; `Dm7` → D Dorian, D Aeolian, D Phrygian + minor pentatonic/blues; `C7` → C Mixolydian, C Lydian Dominant, C Mixolydian ♭6; `Bbmaj7#5` → Bb Lydian Augmented, Bb Ionian ♯5.
- **Scale ghost preview** (single-select toggle): each proposed scale renders as a `<button class="cr-scale-chip">` (full → solid, partial → dimmed) carrying `family` / `modeIndex` from `chordScales`. Clicking the label toggles `scaleSel = {rootPc, name, ivs, family, modeIndex}` ghost (ivs from `data-pcs`) and shows `#scale-details` for that scale; clicking a different chip replaces it, clicking the active one clears selection (details fall back to wired focus if any). A **✦ pin** sets `chordScaleFocus` and calls `applySharedScale` (Explore root/family/mode; pin lights gold when matched) so details stay visible even without a ghost. The active chip gets `.cr-scale-chip.active` (chord-blue fill) and a `ghost notes: …` hint appears in the block title. `renderScaleGhost(midis, area)` renders notes across all strings/frets using the CAGED "All notes" class scheme, all with the `soft` wash (`filter: saturate(.3) brightness(.92)`): the selected scale's root → `root soft` (washed gold), other scale tones → `scale soft` (washed blue), and **non-scale notes → `plain soft`** (the same grey as the old ghost, unchanged). Placed chord notes stay vibrant on top (z-index 10 vs 3). Labels: note name (`names()[pc]`) and chromatic Roman degree (`degreeRoman(rel)`) as before, plus interval quality via `relText(rel)` now gated by `state.showIntervals` like everywhere else. Non-scale positions are skipped entirely when no label toggle is on. Ghost markers are `pointer-events: none`, `z-index: 3` (below the vibrant placed-note markers at 10, above strings), and carry **no** `data-sf` so arpeggio playback only highlights real notes. `renderChordNotes` re-validates `scaleSel` every render (scale must still be a proposal for the current chord root) and clears it otherwise, so the ghost never goes stale; `renderChordNotes` runs before `renderScaleGhost` in `drawBoard`.
- **Note context menu** (right-click a placed note, chords tab only): a body-level `position: fixed` menu (`#ctx-menu`, sibling of `#tip`, z-index 600) with two items.
  - **Pin root**: `state.pinRoot = {s, f}` (or null). When set, `renderChordNotes` passes `pinRootPc(midis)` (the pinned note's pitch class) as the **forced root** into `analyzeChord`, so the chord name, marker colors, intervals, and scale proposals all re-read against it (e.g. E–G–C pinned to E → `Em#5/C`); unpinning restores auto-detection. The pinned note's marker gets a gold `<span class="pin-star">*</span>` at its upper-right corner (`--gold`, text-shadow glow). The pin is cleared automatically when that note is removed (marker click), moved on the same string (neck click), `#btn-chord-clear` pressed, or on load if it no longer matches a placed note. Menu item shows `✦` + "Pin as root"/"Unpin root" depending on the target note. `analyzeChord`'s `forcedRoot` path still evaluates all candidates (so "Also heard as" alternatives remain) but forces the primary; a forced root with no standard reading returns the unmatched result with `rootPc = forcedRoot`.
  - **Relative degrees / intervals**: `state.showIntervalGhost` toggle (persisted). When on (and `state.showDegrees` or `state.showIntervals` is on), `renderIntervalGhost(midis, area)` paints the **whole neck** — every string × every fret 0..N — with ghost markers (`marker plain soft ghost-interval`, z-index 2, `pointer-events:none`, below the scale ghost at 3) labelled with chromatic Roman degree and/or quality relative to the (possibly pinned) chord root. Menu item shows `✓` when active. Ghosts hide when both Degrees and Intervals checkboxes are off, even while the toggle stays persisted.
- **Context menu mechanics**: `openChordMenu(x, y, nt)` (called from the marker's `contextmenu` handler with `preventDefault`+`stopPropagation`) fills `#ctx-menu` and `positionCtx(x, y)` clamps it to the viewport like the tooltip. Menu actions call `render()` then `closeCtx()`. It closes on any document `click`/`contextmenu` outside it, `Escape`, `scroll` (capture) and `resize`.
- `computeData()` returns empty markers for the chords tab; `#scale-details` shows only when a proposal is selected or ✦-wired (`resolveScaleDetailsTarget`); the playback panel stays caged-only. Legend shows a placement hint.

## Markers (`makeMarker`, `js/app.js`)
- 35px circle, `translate(-50%,-50%)`, centered on `bandCenter(fret)`, vertically on the string row.
- Markup: `.mtop` first line = note name `.mn` + Roman degree `.ms`; optional divider `.ml` + interval quality `.mi` on the second line. **Steps checkbox removed** — Romans are Degrees.
- **Degrees** (`state.showDegrees`, `#ctl-degrees`): chromatic Roman numerals on the **first line** next to the note name via `degreeRoman(rel)` → `CHROMATIC_ROMAN` (`I`, `bII`, `II`, `bIII`, `III`, `IV`, `bV`, `V`, `bVI`, `VI`, `bVII`, `VII`) everywhere (markers, ghosts, chips, scale-details).
- **Intervals** (`state.showIntervals`, `#ctl-intervals`): textbook quality names from `M.QUALITIES` (`P1`, `m2`, `M2`, `m3`, `M3`, `P4`, `TT`, `P5`, `m6`, `M6`, `m7`, `M7`) on the second line via `relText` → `M.formatRel` (degrees flag forced off in `relText` so Romans aren't duplicated). Chord chips join with ` · `.
- Legacy: `M.DEGREES` / `M.INTERVALS` still used for chord role shorthand (`roleLabel`). Old saves: `showSteps` migrates into `showDegrees`; pre-split `showIntervals: true` alone still becomes Degrees on / Intervals off.
- CSS vars: `--mc` (shape/chord color), `--mcL` (split left), `--mcR` (split right). `makeMarker(pc, fret, stringIdx, midis, label, cls, color, colorR)`.
- Classes: `marker root|chord|scale|plain`, plus `shaped` / `shaped split` / `soft`. `.marker.root` = gold w/ glow; `.marker.shaped` = shape `--mc` (CAGED non-roots); `.marker.shaped.split` = 50/50 `--mcL`|`--mcR`; `.marker.scale` without shaped = `--blue` (full-scale view); `.marker.plain` = `var(--plain-bg)`, text `--muted`.

## Profiles tab (`state.tab === 'profiles'`, module `js/profiles.js`)
- A guitar-library tab: hide the whole board + controls (`applyTabUI` hides `#ctl-main-controls`, `#board-wrap`, `#legend`, `#tipbox`, `#scale-details`, `#ctl-playback`); `render()` returns early after `profiles.renderProfiles()`. Nothing else reads the board state on this tab. `app.js` creates the module once in `init()` via `FretProfiles.create(deps)` and calls `profiles.bind()` from `bindEvents()`.
- **Data model** (`state.profiles`, `state.profileSeq`, `state.activeProfileId`, persisted in `STORE_KEY`): each profile is `{ id, name, construction, role, scaleLen, fretCount, tuning, photo, desc }`. `tuning` is an array low→high of `{ n: pc, o: octave }` (octave 0–6). `loadState()` / `sanitizeState` in `app.js` sanitizes every field (valid construction/role via `FretProfiles.CONSTRUCTION_OPTS` / `ROLE_OPTS`, `scaleLen` clamped 20–40, `fretCount` clamped 15–24, `desc` sliced to 255 chars, tuning filtered to ≤10 valid `{n,o}`, photo kept only if a data-URL string < 1.5 MB); empty tunings fall back to `FretProfiles.ROLE_DEFAULTS`. `profileSeq` = max(saved seq, max id) so ids never collide; `activeProfileId` is kept only if it still matches an existing profile.
- **Taxonomy** (on `window.FretProfiles`): `CONSTRUCTION_OPTS` — electric · solid body, electric · semi-acoustic, electric · hollow body / archtop, acoustic · steel string, acoustic · classical / nylon, acoustic · resonator. `ROLE_OPTS` — Guitar / Bass / Baritone. `SCALE_PRESETS` datalist (22.5–36″). `ROLE_DEFAULTS` seed tuning + scale length + fretCount + construction per role (guitar std6/25.5/22, bass EADG/34/20, baritone BEADF#B/27/22).
- **Grid**: `.profile-grid` is `grid-template-columns: repeat(5, 1fr)` — cards fill left→right, top→down. Every card shows photo (or `PROFILE_PLACEHOLDER` SVG), name, a **fixed-height description block** (42px, overflow hidden, italic `--faint` "No description yet" placeholder when empty), construction+role chips, scale length + fret count (gold), and the tuning as `E2 A2 D3…`. A trailing `.profile-add` card (dashed border, big `+`) is always last. Clicking a card opens Edit.
- **Card tools** (inline stroke SVGs `.profile-ico`, 14px, `currentColor`): grip (6-dot reorder) top-left `.profile-grip`; top-right `.profile-btn` circles — trash `[data-del]` deletes (confirm modal), check `[data-use]` toggles **"use across Fretboard Lab"** (`state.activeProfileId`) — only ONE guitar can be active; active = green glowing bg + `.profile-card.active` green ring, inactive = same muted style as delete. copy `[data-copy]` duplicates the guitar (same tuning/photo/desc, name + " (copy)", id = `++profileSeq`, never auto-activates). Deleting the active guitar clears `activeProfileId`.
- **Reorder (drag & drop)**: a `.profile-grip` (☰, top-left circle) on each card initiates a **pointer-based drag** (no native HTML5 DnD — `draggable` stays off). `mousedown` on the grip arms the drag (only left button, `preventDefault` stops text selection); the drag activates after the pointer moves >4 px from the start point (`.drag-src` dashed gold + dimmed, siblings dimmed via `.profile-grid.dragging`). `document`-level `mousemove` reorders the live DOM via `insertBefore` (split by the over-card's horizontal midpoint, skipping the `.profile-add` card) so the card visually slides between slots. `mouseup` commits: reads the DOM order back into `state.profiles` (ids via `dataset.id`), `renderProfiles()` + `saveState()` — **order persists** (it's array order in `state.profiles`, which also survives export/import). A window `blur` resets a half-finished drag (release outside the window).
- **Add/Edit modal** (`openProfileModal`): shared `.modal-overlay`/`.modal`. Fields: photo upload (file → **crop editor**, see below), name, Type, Role, scale length (number + datalist), Frets (15–24 + datalist), a full-width **Description** textarea (`maxlength=255`, live `n/255` counter overlay), and a **tuning editor** — rows low→high labelled `str n`, each a note select (respects `names()`/flats) + octave select. `+ string` prepends a low string a perfect 4th down (7-string F#BEADGBE math); `− string` removes the lowest. Until the user edits anything (`editTouched`), changing Role re-seeds tuning + scale length + frets from `ROLE_DEFAULTS`.
- **Photo crop editor** (`openCropEditor`, replaces `readImageFile`): picking a file opens an inline crop UI in the photo box (`.crop-wrap` / `.crop-stage` / `.crop-box` / `.crop-handle`). The image is shown at ≤340×280 px (never upscaled); a **fixed 4:3 crop window** (matches the card's `.prof-photo` `aspect-ratio: 4/3`) starts largest-and-centered, then the user drags the box to move or its gold corner handle to resize (kept 4:3, clamped to the image, min 48 px wide). The area outside the window is dimmed by the crop box's `box-shadow: 0 0 0 9999px` (clipped by the stage's `overflow: hidden`). **Apply** canvas-renders exactly the selected region to **900×675 JPEG q0.78** → `pendingPhoto`; **Cancel** restores the previous photo (new uploads revert to placeholder). Existing photos get a **"Crop photo"** button to re-crop. `restorePhotoBox()` rebuilds the standard photo box + buttons and `bindPhotoControls()` re-wires them; crop document listeners self-clean via a `document.body.contains(cb)` guard. Output is always exactly 4:3, so the card's `object-fit: cover` never crops it further. **Robustness**: an empty `src`, a decode failure (`io.onerror` — e.g. iPhone HEIC), or zero `naturalWidth/Height` replaces the stage with a `.crop-error` message and disables Apply (Cancel still works); Apply is wrapped in try/catch so a draw/canvas failure can't leave the UI dead.
- **Delete**: `confirmDeleteProfile(id)` opens a confirm modal ("Are you sure you want to remove <name>?"); Remove filters it out, clears `activeProfileId` if it was active, and persists. Backdrop click + `Esc` close any modal; Cancel/`×` close without saving. `saveState()` returns bool — the profile save path alerts on localStorage quota overflow.

## Board source (Strings / Tuning / Frets)
- The old **Strings**, **Tuning**, **Frets** selects and the **custom-tuning panel** are GONE (removed from HTML/CSS/JS). The fretboard's strings/tuning/frets now come from the active guitar profile.
- `activeProfile()` = profile matching `state.activeProfileId` (or null). `syncBoardSource()` (top of `render()`) sets `state.stringCount`/`state.fretCount` from the active profile's tuning length + `fretCount`; with no active profile it falls back to the **built-in Standard guitar** (`DEFAULT_TUNING_ID = 'std6'`, `DEFAULT_FRET_COUNT = 15`).
- `tuningMidis()` returns the active profile's midis (`profiles.strToMidi` per string) or std6 midis when none is active. The old `tuningId`/`customPcs` state fields are still saved/loaded for backward compat but no longer affect the board.
- `renderGuitarChip()` fills `#ctl-guitar` (a `<details class="guitar-picker">` in shared controls on Explore/Chords): summary chip shows active guitar (name + tuning + frets; green when a profile is active; photo thumb or `res/guitar-default.png`; built-in **Standard** when none). Bound once via `bindGuitarPicker()`.

## Export / Import (ZIP backup)
- Implemented inside `js/profiles.js` (wired by `profiles.bind()`). **Header buttons** (`.profile-head-actions`): `#prof-export` → `exportSettings()`; `#prof-import` opens `#prof-import-input`; status in `#prof-import-status` (green `.ok` / red `.err`, auto-clears after 6 s).
- **Format**: a hand-rolled ZIP archive (STORE method, no compression, no external libraries). Two entries: `manifest.json` and `fretboard-lab-state.json`, both `{ app: 'fretboard-lab', schema: 1, exportedAt, state: serializeState() }`. Download name: `fretboard-lab-export-YYYY-MM-DD.zip`. Fully verified against .NET `ZipArchive` (structure + CRC) and against the standard CRC-32 test vector.
- `makeZip(entries)`: writes local headers (30 + name), data, central directory (46 + name), and EOCD (22) with `DataView` little-endian setters; version 20, method 0, `crc32` via `CRC_TABLE` (reflected poly `0xEDB88320`, Uint32Array). `concatBytes()` stitches all parts.
- `parseZip(buf)`: scans the tail (last 65 557 bytes) for the EOCD signature, reads entry count + central-dir offset/size, walks central headers, rejects non-STORE methods / ZIP64 sentinels / disk ≠ 0, verifies each local header signature + name/extra lengths, bounds-checks data, and **verifies CRC per entry** (`crc32(data) !== crc → throw`). Returns a `Map` of name → `Uint8Array`.
- `importSettings(file)`: rejects files > 50 MB; `FileReader.readAsArrayBuffer` → `parseZip` (failure → "not readable as a ZIP" status), must contain `fretboard-lab-state.json`, valid JSON, `app === 'fretboard-lab'` with an object `state`, and `schema` ≤ 1 (higher → "newer version" message).
- `confirmImport(rawState, importedCount)` opens the shared modal explaining the replacement (current count vs imported count); **Import** applies `sanitizeState(rawState)` (from `app.js` deps), sets `state.tab = 'profiles'`, then `saveState()` + `syncControls()` + `applyTabUI()` + `render()`, and shows a green status.

## Misc
- Sound (`js/audio.js`): Web Audio **Karplus–Strong** plucked-string synth (noise burst → delay-line average filter, no sample files) plus body/brightness peaking EQ, sweeping lowpass, gain envelope, and a light compressor on a shared master bus. Duration scales with pitch (~1.4–2.4s). `app.js` keeps `playMidi` / `playSequence` aliases from `FretAudio.create(...)`.
- **Arpeggio player**: `playSequence(notes, rootOverride)` schedules notes at `gap = 60000/bpm` ms; `orderNotes` applies groove and marks `.marker.playing`. Used by CAGED boxes and `#btn-chord-play`.
- `#tip` tooltip: body-level fixed table. Markers → Note, Fret, Degree, Interval (abbr + full name via `M.qualityFull` / compound variants on chords; no midi). Analyzed chord name (`.cr-name`) → Root, Quality, Extension, Alteration, Bass from the structured symbol parts (absent quality mark with a major 3rd → tip shows `major`; `m` when minor; dim/aug/sus stay `—`).
- Legend: CAGED has no `plain` swatch; scales adds one only when `fullChart` is on.
